# TripFlip V3 1차 구현 기록

## 사용자 목표

목적지를 모르는 사용자가 가능한 날짜·박수·다양한 일행·서로 다른 취향·총예산·숙소 선호를 입력하고, 개인화한 여행지 순위에서 일정·식사·예약 검색·저장까지 진행한다.
무료 운영을 원칙으로 사용자 조회 시 유료 AI나 가격 API를 호출하지 않는다.

## 이번 변경의 기준

가족 조합별 데이터베이스를 만들지 않는다. 장소 속성과 구성원 조건을 조합해 계산한다.
관계나 성별만으로 취향을 확정하지 않는다. 부모님 관계만으로 급경사를 강제 제외하지 않는다.
AI 적합도 0점은 검증된 이용 금지와 다르다. 현재 확인된 제한 자료가 없어 해당 값은 선호 감점에만 사용한다.
향후 근거 있는 연령·키·정원 제한이 확보되면 검증 상태와 함께 필수 조건 검사에 연결해야 한다.

## 데이터 경로

기존 TS 자료와 표준 CSV/JSON → 원본 보존 → 형식·범위·권역·중복 검사 → 검수 대기/격리 → 내용 해시를 고정한 검수 승인 → SQLite와 정적 JSON.
값마다 출처·확인일·확인/추정/미확인 상태를 둔다. 라이선스나 정체성 근거가 없으면 새 공개 카탈로그 승인을 보류한다.
Wikidata 이름·좌표 승인과 AI 여행 등급을 분리한다. 새 미평가 장소에 임의 등급을 채우지 않는다.
공개 승인 자료의 동일 ID·alias·같은 권역 내 정확한 영문명으로 기존 장소의 확인된 기본 사실만 보강한다.

## 점수와 경비

공통/개인 핵심 취향의 충족과 등록 장소의 경험 등급, 동행 적합 추정, 이동 부담, 월별 기후를 사용한다.
추천 장소 수는 도착·귀국일을 반영한 공통 dayVisitCapacity를 사용한다.
자료가 모자란 자리에 0점을 넣어 여행지의 매력 부족으로 단정하지 않고, 후보 수를 별도로 표시한다.
일정 배치를 위한 동선·취향 보완 보너스와 화면의 0~100점 적합도는 구분한다.

일행 총경비 = 1인 항공 가정×전체 인원 + 객실 1박 가격 가정×객실 수×숙박 수 + 1인 식비 가정×전체 인원×여행일수.
객실 수 미정일 때 전원 2인/객실은 비용 산정 가정일 뿐 실제 투숙 가능 판정이 아니다.
현지 교통비·입장료·보험·연령별 실제 항공/숙박 할인을 포함한 확정 견적은 아니다.
상한 모드는 확인 가능한 예상 경비가 넘으면 제외하고, 유연한 목표는 적합도와 안내에 반영한다.

## 저장과 예약

예약처 이동과 실제 예약 완료를 구분한다. 현재는 일반 검색 링크와 사용자 직접 완료 표시다.
숙소 수준·객실 수 변경은 예상 경비에 반영한다. 항공 선호는 저장하지만 실제 항공사 목록/가격 필터는 아직 연결하지 않는다.
저장 계획에 조건·일정판·기상/조식 설정을 함께 보관한다. 다른 조건의 여행이 기존 저장 계획을 덮어쓰지 않는다.
저장이 실패하면 성공으로 이동하지 않고 파일 다운로드를 안내한다.

## 후속 데이터 작업

시범 권역의 실제 식당 자료·메뉴 분류·접근성, 청결 근거·정원·침대·자녀 정책 등 숙소 정보를 우선 보강한다.
기존 세계 자료의 출처와 명칭·좌표 일치를 검수한다. 원본을 보존하고 잘못된 식별자나 중복을 검수 결과로 관리한다.
운영 규모와 상용 사용 조건을 확인한 무료 호스팅을 선택한다. 자동 유료 전환에 의존하지 않는다.

## 검증 방법

타입 검사, 가족 구성/취향/예산/박수 회귀 테스트, 일정/고정칸/조식/시간대 테스트, 저장 스냅샷과 예약 URL 테스트, 적재·권리·출처·검수 해시·중복·격리 테스트를 수행한다.
모바일 브라우저에서 조건 입력→결과→일정→조식 설정→예약 검색→저장→새로고침/다른 조건 후 복원을 확인한다.
이 문서의 구현 범위는 전 세계 상용 데이터가 완성됐다는 의미가 아니다.
