# TripFlip · 무료 데이터 기반 개인화 여행 플래너

다른 개발자·AI에게 넘길 때는 [인수인계 문서](HANDOFF.md)를 함께 전달하세요.

여행 조건 → 여행지 비교 → 일자별 일정·식사 수정 → 항공·숙소 검색 → 계획 저장.
기존 앱을 확장한 개발 버전입니다. 실행 중 유료 AI API나 별도 유료 DB를 사용하지 않습니다.

## 실행

Node 24 이상, npm, Python 3.10 이상을 사용합니다.

```bash
npm ci
npm run dev
```

기본 주소는 http://localhost:3000 입니다. API 키 없이 실행됩니다.

```bash
npm run typecheck
npm test
npm run test:catalog
npm run build
```

브라우저 검증은 개발 또는 실행 서버를 켜 둔 상태에서 수행합니다.

```bash
npx playwright install chromium
npm run test:e2e
```

## 구현 범위

- 구성원별 관계·실제 나이·보행 부담·유모차·개인 취향. 성인 자녀를 성인으로 계산.
- 공통 핵심 취향을 동등하게 반영하고, 구성원 개인 취향도 함께 반영.
- 확정 날짜 또는 가능한 기간+희망 박수 입력. 가능한 기간에서는 기준 출발일을 직접 선택.
- 전체 예산 미정·목표·상한, 현지 물가, 숙소 가격 수준, 객실 수 입력.
- 숙박비는 박수, 식비는 여행일수로 계산. 일행 전체 예상 경비 표시.
- 하루 관광 1·2·3곳. 도착·귀국일 시간 가정, 저녁 식사와 야간 관광 분리.
- 일정 칸 고정·재최적화, 음식 종류·디저트 선택, 기상시간·조식 유무 설정.
- 숙소 가격 수준·객실 수 재선택, 외부 검색 링크, 예약 여부 직접 기록.
- 일정판·조식 설정까지 계획별 스냅샷 저장. JSON 파일 내보내기.
- 데이터 적재·검수·SQLite·권역별 JSON 생성과 /data-status 출처 화면.

## 무료 데이터 적재

```bash
npm run catalog:extract
npm run catalog:build
npm run catalog:import -- data/imports/wikidata-pilot.json --replace
npm run catalog:build
```

검수 승인은 해당 레코드 내용을 확인한 뒤 CLI의 review 명령으로 기록합니다.
기존 승인 원장은 data/catalog-reviews.json이며 내용 해시가 달라지면 재검수가 필요합니다.
자세한 형식과 명령은 [데이터 계약](docs/data-contract.md)을 참고하세요.

- 원본 스냅샷·작업 DB·검수 대기·격리 자료: data/generated/ (Git 제외)
- 출처 확인 입력 자료: data/imports/
- 확인 내용에 고정된 승인 원장: data/catalog-reviews.json
- 앱에 배포하는 승인 자료: public/catalog/ (승인되지 않은 전체 원본을 공개하지 않음)
- 앱은 승인된 명칭·좌표만 기존 장소에 보강하며, 기존 AI 등급을 검증된 등급으로 승격하지 않음.

기존 164권역·3,649개 세계 장소와 시범 자료, 호텔 후보를 보존했습니다.
기존 자료의 이용 조건·정체성·최신성 검토는 진행 중입니다.
시범 5권역과 10개 장소의 이름·좌표를 Wikidata 공식 API에서 확인한 소규모 자료부터 연결합니다.
확인 범위와 발견한 식별자 오류는 [출처 기록](docs/pilot-sources.md)에 있습니다.

## 식당·선택 화면 개선

- 동행 간편 선택과 구성원 설정창을 제공하고 객실·지역 물가·반려동물 설정은 접었습니다.
- 식당은 종류 필터·검색·8개 후보부터 선택합니다. 세부 출처는 펼쳐서 확인합니다.
- Wikivoyage에 등록된 식당 105곳과 카페 12곳을 CC BY-SA 4.0 조건으로 연결했습니다.
- 주소만 있는 후보에는 좌표를 만들지 않고 자동 동선 추천에서 제외합니다.
- 식당에 별점·가족 등급·유아 편의시설을 임의로 채우지 않습니다.
- 가이드 원문은 data/imports/sources/wikivoyage, 배포용 자료는 public/dining/catalog.json입니다.

```bash
npm run dining:build
```

이 명령은 보존한 원문의 내용 해시·리비전·이용 조건을 검사하고 SQLite(data/generated/dining.sqlite)와 정적 JSON을 생성합니다. 앱 사용 중 외부 AI나 데이터 API를 호출하지 않습니다.
자세한 범위는 [식당·선택 화면 개선 기록](docs/dining-and-selection.md)을 참고하세요.

## 현재 한계

- 추천 적합도·피로도·체류·이동시간·경비는 추정이 포함됩니다.
- 실제 날짜별 항공·숙박 가격, 객실 정원·청결 세부평점·영업시간을 보장하지 않습니다.
- 가능한 날짜 중 최저가 자동 탐색, 항공·숙소 확정 후 실제 동선 재계산은 아직 연결하지 않았습니다.
- 음식 분류는 확보한 장소 태그와 명칭을 사용합니다. 식당·디저트 후보가 부족하면 미정으로 남깁니다.
- 기존 나트랑 가상 식당 11개는 새 공개 카탈로그와 현재 추천 흐름에 사용하지 않습니다.
- 계획은 현재 기기·브라우저에 저장됩니다. 파일 내보내기는 보관용이며 계정 동기화·파일 가져오기는 없습니다.
- 제휴 계약 전이므로 외부 링크는 일반 검색 링크입니다. 예약 완료 표시는 사용자 직접 확인입니다.
- 무료 호스팅에도 이용량·상업 사용 조건이 있습니다. Vercel Hobby는 개인·비상업 용도라 상용 배포는 Cloudflare Pages(무료, 상업 가능)로 옮깁니다. 앱은 정적 내보내기(`out/`)입니다.

설계·검증 범위는 [V3 구현 기록](docs/implementation-v3.md)을 참고하세요.
초기 MVP의 역사적 기록은 [legacy-mvp.md](docs/legacy-mvp.md)에 보존했습니다.
